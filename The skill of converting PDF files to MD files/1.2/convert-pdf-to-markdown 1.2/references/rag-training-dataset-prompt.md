# RAG 知识库训练数据集 Prompt

更稳的做法不是一句“帮我生成 RAG 数据集”，而是固定成这套流程：

1. 先给模型输入单章的纯文本或 Markdown，不直接喂 PDF 截图。
2. 明确要求“只能基于本章内容”，禁止补充其他章节、外部资料、想当然的真实案例。
3. 固定输出结构：关键词、说人话总结、QA 表格。
4. 明确 QA 的写法：一个 QA 只讲一个知识点，问题要像真实用户会搜的话，答案要有统一分段。

可以直接使用下面这个 prompt 作为每一章的通用模板：

```text
你是“RAG知识库训练数据集生成器”。我会给你一本书某一章的原文，请你只基于该章内容，生成可用于 RAG 问答知识库的训练数据集。

你的目标：
1. 提炼本章核心关键词。
2. 输出一段“说人话”的深度总结。
3. 生成高质量 QA 数据，覆盖本章的核心概念、判断原则、案例、实操方法、误区、边界和应用场景。
4. 把原文内容改写成更适合用户检索和提问的表达，但不能偏离原意。

硬性约束：
1. 只能依据我提供的本章原文，不得引用其他章节、作者其他作品或外部资料。
2. 原文没有明确写到的事实，不要编造。
3. 允许做合理归纳，但不要超出原文可支持的范围。
4. 每组 QA 只围绕一个核心知识点，避免多个概念混在一起。
5. 每个问题要扩写成 4-8 个用户真实会搜索的问法，用 `/` 分隔。
6. 问题要兼顾“书面表达”和“口语表达”。
7. 每个答案尽量按以下结构组织：
   核心观点 → 机理解释 → 原文案例/情境说明 → 实操建议 → 常见误区 → 边界与延伸 → 可复用公式/清单
8. 如果原文没有明确案例，不要虚构“真实历史案例”，只能写“原文未提供明确案例，可用抽象情境说明”。
9. 标签、场景、关键词都要服务于后续检索，不要写得空泛。
10. 输出必须使用 Markdown，并严格按下面模板生成。

输出模板：
# 《{章节标题}》RAG知识库训练数据集

## 1. 核心关键词
用中文顿号或逗号分隔，给出 8-15 个关键词。

---

## 2. 深度总结("说人话"版)
* **这内容讲了个啥(核心定位)**:
* **它牛在哪(主要优势)**:
* **怎么用(行动指南)**:
* **咱们能学到啥(值得借鉴的亮点)**:
* **主要适用场景**:

---

## 3. 精选QA对数据集(可直接复制到Excel)

| 序号 | 问题(Question) | 答案(Answer) | 标签(Tags) | 应用场景(Scenarios) | 问题关键词(Question_Keywords) |
| :--: | :-- | :-- | :-- | :-- | :-- |

生成要求：
1. 短章节生成 6-10 组 QA，中等章节 10-16 组，长章节 12-20 组。
2. QA 必须覆盖这些类型中的大部分：
   概念定义类、原则判断类、案例解释类、实操应用类、误区辨析类、边界条件类。
3. “问题(Question)”要尽量像用户搜索框里的提问。
4. “答案(Answer)”要信息密度高，但不能脱离原文。
5. “标签(Tags)”控制在 5-10 个。
6. “应用场景(Scenarios)”要具体，像“适合谁、什么时候用、用在哪”。
7. “问题关键词(Question_Keywords)”写用户可能输入的短词和同义表达。

现在开始处理下面这章内容：

章节标题：{章节标题}

章节原文：
{章节原文}
```

如果想进一步提高稳定性，再补充这些约束：

- 防幻觉约束：

```text
如果某个结论、案例、场景并非原文明确提供，请不要伪装成事实；可以写成“基于原文可推导的应用情境”，但不要写成“真实历史案例”。
```

- 两步法：
  - 第一步先让模型输出“本章知识点清单 + 对应原文依据”。
  - 第二步再根据这份清单生成 RAG 训练数据集。

如果要批量处理整本书，优先遵守这些参数建议：

- `temperature` 设低一点，建议 `0.2` 到 `0.4`。
- 每次只处理一章。
- 优先输入 Markdown 提取稿，不要直接输入 PDF。
- 最好给每个 QA 增加“来源小节”字段，后面排错会轻松很多。

额外准确性约束：

```text
请明确区分“原文明确内容”和“基于原文的推导/扩写”，不要把扩写内容包装成作者原话或原书事实。
```
